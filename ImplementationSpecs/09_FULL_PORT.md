# 09. Полный перенос сценария, ресурсов и эффектов

## Цель и зависимости

Зависимость: 08, все Reference manifests и инструменты 04. Перенести весь достижимый контент без пропуска реплик и сюжетных операций. Запрещено компенсировать недостающий runtime C++-логикой конкретной новеллы.

## Порядок переноса

1. Полный пролог и запуск из главного меню.
2. Центральный выбор и посещение первой локации.
3. Свалка, офисы, столовая с исходными labels/calls/returns.
4. Варианты посещений при var_roots=2/3, условия счетчиков и visited-флаги.
5. Ending dispatcher и восемь завершений.
6. Полный визуальный/аудиопроход, эффекты и переходы.

Импорт выполнять подготовленным конвертером; запуск инструмента делает пользователь. Агент исправляет обнаруженные ошибки в parser/manifest и обеспечивает повторяемость, а не правит generated Story в обход pipeline. Для ручного исключения нужен стабильный source mapping и запись причины.

## Сюжетная точность

Имена и значения исходных семи variables сохраняются. Начисления +0/+1/+2, точка изменения var_roots, visited assignments, условия повторного выбора и все `block_rollback` переносить точно. Не упрощать цепочку Call/Return в Jump, если это меняет точку продолжения.

Концовка определяется тремя boolean признаками score>=5; для каждого score<5 признак false. Существуют восемь сочетаний 000..111. Привязка к label и показываемому номеру берется из ENDINGS registry, не выводится из бинарного номера. Не менять отдельные if исходника на fall-through, при котором запускаются несколько концовок: каждое выбранное окончание завершает сессию по оригинальному full_restart-смыслу. При завершении сохранить профиль, удалить transient state и вернуться в уже знакомое главное меню с его музыкой.

Все русские строки и punctuation сохранить. Допустимы только нормализации Unicode/markup, описанные в контрактах и дефектах. Не исправлять шутки, опечатки литературного текста и стилистику без отдельного запроса. Заголовок, имена, credits и обозначения 1/8..8/8 должны остаться узнаваемыми и соответствовать source.

## Визуальная точность

Перенести задействованные backgrounds/CG/character states с исходной прозрачностью, filtering и пропорциями. Сначала один фиксированный viewport 1920×1080, затем адаптация только средствами layout. Anchor/pivot/scale conversions записать в Reference. Недопустимо индивидуально сдвигать персонажей «на глаз», чтобы скрыть ошибку общей формулы.

Поддержать все фактически используемые варианты bold/italic/size/alpha/cps/wait/nw/underline/strike и wave/shake. Для wave фиксировать из исходного Ren’Py shader фактические единицы amplitude/frequency/wavelength и фазовую формулу, не выбирать похожую синусоиду. Если встроенный shader wave не определен в project sources, извлечь его определение из установленной версии Ren’Py, использующейся для baseline; указать version и source. Это обязательная проверка, не предположение о параметрах.

Shake использует исходные коэффициенты 13/17 и time/speed/amplitude из shaders.rpy. Материалы проекта на SRSL используют общий glyph-effect API движка. Blur/chromatic/glitch, bubble/input и Алиса включаются только при достижимости по registry. Неиспользуемые ресурсы не удалять из исходника.

Проверить malformed scene names (например употребление без `bg`), empty sprites и voice paths; применять только однозначные aliases из DEFECTS. При несуществующем нужном CG не подставлять похожую картинку: такой участок остается блокирующим дефектом с точной ссылкой.

## Аудио

Каждый music/sound event должен иметь исходную команду, resource ID, loop/fade и target bus. Сохранить относительный баланс исходных default volumes. Офлайн-conversion неподдерживаемого используемого формата должна быть lossless для PCM либо документированной для сжатого исходника; проверить duration/sample rate/channels и отсутствие обрезанного начала. Не перекодировать OGG/WAV без необходимости.

## Проверки покрытия

Подготовить `Reference/PORT_COVERAGE.md`: исходные исполняемые узлы, перенесенные команды, resources и tags, отсутствующие/исключенные с причинами. Coverage всех достижимых узлов — 100%, неизвестных конструкций — 0. Отдельно static graph coverage и фактически пройденные ветви.

Подготовить deterministic playthrough fixtures для всех шести перестановок трех локаций и каждого достижимого окончания. Для полного теста source boolean visit/score conditions недостаточно: trace должен включать реальные принятые choices, counter deltas и итоговые predicates. Где полное пересечение order×ending недостижимо, внести объяснение в matrix; не требовать несуществующий путь и не менять сюжет ради теста.

## Приемка и отчет

Start начинает оригинальный пролог; новая игра после конца не наследует прошлые counters или персонажей. Все восемь окончаний доступны по воспроизводимым путям либо зарегистрирован исходный блокирующий дефект. Missing resource warnings и unsupported statements отсутствуют. Создать `Reports/09_RESULT.md` с contentVersion, coverage, mapping ошибок и сравнениями. Этап не принят, если хотя бы одна достижимая ветвь заменена заглушкой.
