# 00. Общие обязательные контракты

## 1. Область и приоритет решений

Целевая поставка v1: Windows x64, мышь и клавиатура, русский язык, оконный и полноэкранный режим. В исходниках не ломать существующие платформы движка. Android, Web, облачная синхронизация, перенос старых Ren’Py-сохранений, TTS и дополнительные языки в v1 не входят. Стандартные экраны Ren’Py, которые не достижимы в оригинальном пользовательском потоке, не переносить автоматически. Галерею концовок не добавлять.

Источники истины: эти требования для архитектуры и принятых решений; исходные `.rpy`/`.py` для содержания, ветвлений и параметров; проверенный запуск оригинала для фактического поведения. При конфликте исходника с запуском сначала проверить, что запускается та же версия, без устаревших `.rpyc`. Исправления оригинальных дефектов перечислять отдельно; запрещено незаметно менять содержание, начисление очков или переходы.

В именах ниже обозначены обязательные роли и форматы данных. Это не заявление о существовании одноименных методов C++ API. Агент обязан найти реальную реализацию и расширить ее минимально, затем записать фактические сигнатуры в отчет.

## 2. Разделение ответственности

В C++ разрешены только универсальные возможности: layout, текст и его измерение, изображения, ввод/фокус/модальность, сигналы UI, чтение ресурсов, аудиовоспроизведение, сериализация значений, атомарное хранение слотов, получение миниатюры.

В AngelScript обязательны: исполнитель сценария, условия/очки/концовки, персонажи, ADV/NVL, меню и его параллакс, музыкальные события/fade, паузы текста, звук печати, политика сохранений, восстановление состояния, история, откат, skip/auto, настройки, debug-инструменты игры. GPU-операции символов могут выполняться общим C++/SRSL-механизмом; параметры и выбор эффекта задаются игрой.

Запрещено добавлять в движок VN-specific interpreter, Ren’Py parser/runtime, сюжетные команды, названия героев, зависимости от путей DeathLovers. Редакторский конвертер находится в проекте игры и не используется в runtime. Нельзя использовать ImGui, HTML, Yoga/Flexbox или ручную альтернативную раскладку для игрового UI.

## 3. Структура проекта

В `Resources/DeathLovers`: `Scripts` — AS; `Story` — сценарий и таблицы; `Scenes`, `Prefabs`, `UI`, `Images`, `Audio`, `Fonts`, `Materials` — соответствующие ресурсы. Инструменты преобразования: `DeathLovers/Tools`; данные проверок и реестры: `ImplementationSpecs/Reference`; отчеты: `ImplementationSpecs/Reports`. Формат сцен/префабов — существующий нативный формат SREngine; его нельзя придумывать или подменять самодельным runtime-загрузчиком.

Игровые настройки и saves не пишутся в Resources или каталог установки. Пользовательские данные хранятся в каталоге приложения DeathLovers через платформенный API движка. Группы хранилища: `profile`, `manual`, `quick`, `auto`.

## 4. UI и Unity

Эталон: семантика Unity uGUI 2.0.0, не UI Toolkit. Зафиксировать точный исходный архив/commit пакета и SHA-256 в этапе 02; не использовать плавающий `main`. Canvas reference resolution — 1920×1080, Scale With Screen Size, Match Width Or Height, match=0.5. Все игровые экраны используют один корневой Canvas; сцена новеллы вписывается в 16:9 без обрезки, свободное место заполняется черным. Масштаб Canvas и вписывание сцены — разные операции, двойное масштабирование запрещено.

Inspector-параметры, соответствующие Unity, принимают те же значения и имеют ту же семантику. Конвертация старых данных SREngine допустима только явной миграцией с версией; скрытые поправки координат в игровых скриптах запрещены. Координаты Ren’Py переводятся один раз при импорте/в слое представления игры по документированной формуле; это не изменение семантики layout.

## 5. Исполнение и идентичность сценария

Исполнитель — конечный автомат в AS с явными `currentCommandId`, `phase`, `callStack`, переменными и описанием представления. `phase`: `Ready`, `WaitingText`, `WaitingChoice`, `WaitingTimer`, `WaitingTransition`, `Finished`. При `Ready` выполняется следующая команда; остальные фазы блокируют переход, пока не выполнено их условие. Таймеры используют игровое монотонное время, не системные часы.

Команды и варианты выбора имеют неизменяемые строковые ID. Номер строки, порядковый индекс команды и текст реплики не являются идентификаторами. ID назначаются через сохраняемый manifest; изменение текста существующей реплики сохраняет ID. Конвертер обязан останавливать неоднозначное сопоставление, а не переназначать ID молча. Manifest и его изменения входят в контроль версий.

Сценарий хранится как UTF-8 JSON: `schemaVersion=1`, `contentVersion`, `entryCommandId`, таблица `commands`, таблица `labels`. Разбор JSON — универсальная возможность движка, исполнение команд — AS. Типы команд: `Say`, `NvlClear`, `Scene`, `Character`, `Audio`, `Assign`, `Branch`, `Choice`, `Jump`, `Call`, `Return`, `Wait`, `RollbackBarrier`, `RestartToMenu`. Каждый тип и допустимые поля формально описываются в этапе 04; произвольное выполнение Python или выражений хоста запрещено.

## 6. Состояние сохранения

Логический документ `GameState`, schemaVersion=1:

- `contentVersion`, `currentCommandId`, `phase`, `callStack` (ID возврата в порядке вызовов).
- `variables`: семь исходных переменных — `var_offices_visited`, `var_canteen_visited`, `var_landfill_visited`, `var_roots`, `var_hunger_score`, `var_war_score`, `var_plague_score`; дополнительные переменные только если они найдены в реально исполняемом исходнике и внесены в реестр.
- `presentation`: фон, слои персонажей с state/position/scale/flip/order, ADV/NVL, говорящий, полный текст, видимый индекс, оставшаяся пауза, текущие варианты выбора, состояние перехода.
- `audio`: для долгоживущих источников resource ID, loop, позиция секунд, текущая/целевая громкость и оставшаяся длительность fade.
- `history` (не более 250), `rollbackBoundaryId`, история контрольных точек отката не более 100 записей.
- `playTimeSeconds`, `activeEndingId` либо пустое значение.

Снимки состоят из значений и ID ресурсов. Запрещены указатели, native handles, сериализация стека VM и живые ссылки на scene objects. Проекция состояния на сцену идемпотентна: повторное восстановление не начисляет очки и не исполняет уже пройденные команды.

`ProfileState`, schemaVersion=1: настройки, признак первого запуска, множество прочитанных ID. Прочитанность глобальна для профиля и не откатывается при загрузке/rollback. Состояние сессии и профиль сохраняются раздельно.

## 7. Правила точности и дефектов оригинала

Неизвестная команда, состояние или ресурс — диагностируемая ошибка с путем и строкой, не молчаливый пропуск. Для очевидных опечаток ресурсов разрешена только таблица alias с подтвержденной единственной целью. Несбалансированную визуальную разметку закрывать в конце реплики без протекания на следующую; лишний закрывающий тег игнорировать с диагностикой. Сюжетный смысл и сами слова не исправлять.

Заявленные blur/chromatic/glitch переносить только при достижимом использовании. Неиспользуемая Алиса и стандартные bubble/input/replay-экраны не входят в релиз, если этап 01 не докажет их достижимость. Инструмент обязан сообщать о неиспользуемых ресурсах, но не удалять их.

## 8. Проверки и передача этапа

Каждый `Reports/NN_RESULT.md` содержит: статус; измененные файлы движка и игры раздельно; реальные API и форматы; изменения совместимости; выполненные статические проверки; точные пользовательские шаги runtime-проверок с ожидаемым результатом; непройденные пункты; зависимости следующего этапа. Нельзя называть этап проверенным без результатов запуска.

Не создавать commits, не менять Git safe.directory и не трогать чужие изменения. Перед правкой смотреть состояние файлов доступными безопасными средствами. Если Git недоступен из-за ownership, указать это и использовать сравнение файлов; не исправлять глобальные настройки пользователя.
