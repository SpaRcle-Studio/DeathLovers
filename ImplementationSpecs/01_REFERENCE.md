# 01. Эталон, ресурсы и карта сценария

## Цель и зависимости

Зависимостей нет. Прочитать README и 00_CONTRACTS. Задача — подготовить проверяемый источник данных для всех последующих агентов. На этом этапе не реализовывать игровой runtime и не менять Ren’Py-проект.

## Входные материалы

Изучить `script.rpy`, `screens.rpy`, `gui.rpy`, `options.rpy`, `images.rpy`, `characters.rpy`, `character_data.py`, `audio.rpy`, `shaders.rpy`, `debug.rpy` в исходной игре. `.rpyc`, cache и saves не считать авторитетным исходным кодом. Не копировать ключи Android, keystore, чужие сохранения и cache в игру.

Подтвержденная основа: GUI 1920×1080, Pangolin.ttf; ADV/NVL; три локации; восемь концовок; сетка desktop-сохранений 3×2; история 250; семь слоев главного меню. Полные размеры/цвета/параметры извлечь из реальных исходников, а не из описания предыдущего чата.

## Работы

1. Создать `Reference/SOURCE_BASELINE.md`: абсолютные пути, дата, версия исходника, список файлов и SHA-256 всех исходных сценариев. Записать стартовую метку и последовательность splash/start/menu.
2. Создать `Reference/STORY_MAP.md`: все достижимые метки, call/jump/return, условные выборы, изменения переменных, barriers и окончания. Для каждой сущности указать файл и строку. Отдельно указать, является ли `main_choice` меткой или иным идентификатором по факту исходника.
3. Создать `Reference/VARIABLES.md`: имя, тип, начальное значение, места чтения/изменения. Семь исходных переменных сохранить по именам. Проверить влияние порядка посещений и ограничения повторного посещения.
4. Создать `Reference/ENDINGS.md`: восемь комбинаций предикатов score>=5, точные исходные labels, отображаемый номер и путь достижения. Не выводить номер окончания из порядка файлов. Для каждой комбинации подготовить воспроизводимую последовательность выборов; недостижимость документировать как дефект, а не менять начисления.
5. Создать `Reference/ASSETS.md`: логический ID, исходный путь, целевой путь, формат, dimensions/duration при наличии доступного reader, alpha, filtering, использование. Разрешать поиск audio по правилам Ren’Py; каждую неоднозначность пути считать ошибкой. Сохранить точное написание имен вроде `dissapointed` в исходных ID.
6. Создать `Reference/UI_REFERENCE.md`: достижимые экраны, desktop-строки, layout-параметры, фон, padding, spacing, шрифты, состояния, горячие клавиши, порядок отрисовки. Указать фактически активные определения экранов при дублировании и их условия вариантов.
7. Создать `Reference/TEXT_AND_AUDIO.md`: все используемые теги/параметры, поведение auto_wait, интервалы голоса и персонажи, музыка и fade. Отдельно разобрать `add_auto_waits`, NVL call_in_new_context, временные эффекты.
8. Создать `Reference/DEFECTS.md`: ID, точная причина, воспроизводимость, принятое действие. Допустимые действия — alias, ограниченная нормализация разметки, исключение недостижимого кода, исправление представления без изменения содержания. Сюжетное противоречие нельзя объявлять исправленным без явного решения пользователя; остальной перенос продолжается.
9. Создать `Reference/BASELINE_CHECKLIST.md`: пошаговые действия для пользователя в оригинале и список скриншотов: меню center/corners, ADV, NVL, choice, все вкладки, все концовки. Названия снимков стабильны, например `menu_center_1920x1080.png`.

## Инструменты и ограничения

На этапе можно подготовить декларативные таблицы/машиночитаемые manifests; исполнение новых скриптов запрещено текущими инструкциями движка. Сборку и приложения не запускать. Если screenshots еще не предоставлены, фиксировать `AWAITING_USER_RUN`; не выдумывать визуальный эталон по памяти. Статические значения из исходника уже пригодны для следующих этапов.

## Приемка

- Каждая достижимая исходная метка и операция отражена в карте.
- У каждого используемого изображения, звука и шрифта есть однозначный путь либо зарегистрированная блокирующая ошибка.
- Восемь предикатов концовок проверены на взаимную исключительность и полноту.
- Есть список всех сюжетных выборов и отдельный список стандартных недостижимых экранов.
- Таблицы отличают подтвержденный кодом факт от ожидающего пользовательского запуска поведения.

## Передача

Создать `Reports/01_RESULT.md`, указать количество меток, выборов, реплик, изображений и аудиоресурсов, список исключений и готовые данные для этапов 02–04. Не заменять точные счетчики приблизительными числами.
