# DeathLovers: комплект технических заданий

Дата: 15.11.2026. Версия требований: 1.0.

Цель: полностью перенести новеллу «У Смерти много л(юбовн)иц!» из Ren’Py в SREngine. Движок остается универсальным C++ движком; вся логика игры исполняется отдельными AngelScript-скриптами проекта DeathLovers. Этот комплект описывает будущую реализацию, а не подтверждает наличие работающих функций.

## Обязательное чтение для каждого агента

1. Этот README.
2. [Общие контракты](00_CONTRACTS.md).
3. Выданный файл этапа и отчеты его зависимостей в `Reports`.
4. `C:/Work/SREngine/AGENTS.md`, `C:/Work/SREngine/CLAUDE.md` и применимые вложенные инструкции перед изменением движка.

Все этапы выполняются последовательно. Каждый файл — самостоятельное задание, но не разрешение обходить незавершенные зависимости. После реализации агент создает `Reports/NN_RESULT.md` рядом с этими документами. Изменять исходные ТЗ для маскировки невыполненных требований запрещено.

## Как выдавать задание агенту

Передать агенту путь к README и нужному этапу. Формулировка: «Реализуй этап NN по ImplementationSpecs/NN_*.md, соблюдая 00_CONTRACTS.md. Сначала прочитай Reports зависимостей. Заверши отчетом Reports/NN_RESULT.md. Не переходи к следующему этапу».

## Статусы и запрет фиктивной приемки

- `IMPLEMENTED`: код/ресурсы подготовлены, статические проверки проведены.
- `AWAITING_USER_RUN`: сборка или проверка в запущенном приложении ожидает пользователя.
- `VERIFIED`: все обязательные проверки подтверждены результатами пользователя.
- `BLOCKED`: конкретная обязательная проверка или зависимость не выполнена; указать причину и остаток работ.

Согласно CLAUDE.md агент не запускает сборку, CMake, кодогенерацию, исполняемые файлы движка, тесты и скрипты самостоятельно. Он готовит реализацию, данные проверок и точные инструкции пользователю. Этот запрет распространяется и на написанные в рамках этапов конвертеры. Подготовка проверки не равна успешному прохождению. Следующий этап можно готовить по готовым контрактам, но нельзя объявлять интеграцию принятой без фактической проверки.

Абсолютную совместимость нельзя подтвердить одним чтением кода: для layout обязательны сравнения с закрепленным эталоном Unity, для новеллы — результаты воспроизведения оригинала. Неполученные доказательства остаются явно незакрытыми критериями, а не заменяются предположениями.
