# 07. Сохранения, загрузка и постоянный профиль

## Цель и зависимости

Зависимость: 06. Довести общий SaveSystem движка до реальной записи и чтения; политику слотов, формат GameState и восстановление реализовать на AS. Каркас SaveSystem не считать готовой реализацией: на исходной проверке Save/Load только обрабатывали каталог, а OpenSlot не десериализовал данные.

## Ответственность C++

Расширить существующие SaveSystem/SaveSlot/VFS/Serialization, не создавать отдельное хранилище новеллы. Предоставить AS операции чтения/записи дерева типизированных значений, enumeration metadata, удаления и clear errors. Операции возвращают подтвержденный результат; void FlushSlot не должен скрывать ошибки от UI.

Каталог приложения должен определяться application identity DeathLovers, не SREngine editor. Разрешены только group/slot IDs, без абсолютных путей и `..`. Список перечисляет данные на диске после нового запуска, а не только m_slots текущего процесса.

Физический слот — каталог group/slotId с поколениями `gen_<monotonic-id>`. Поколение содержит `state.json` UTF-8, `metadata.json`, `thumbnail.png`; состояние профиля не требует картинки. Запись: создать новое поколение; записать payload и metadata с hash/length; завершить flush; атомарно заменить `current` marker в пределах той же файловой системы. До успешной замены marker старый слот остается актуальным. Не изменять файлы текущего поколения на месте. После успеха сохранять предыдущее валидное поколение, удалять только более старые. Восстановление после сбоя читает current, а при его повреждении — последнее полностью валидное поколение с отметкой восстановления. Завершенность проверяется checksum/schema, не фактом наличия каталога.

Metadata: slotId, group, schemaVersion, contentVersion, createdUtc в ISO-8601, playTimeSeconds, currentCommandId, sceneTitle, payloadSha256, payloadLength. Проверять checksum до десериализации. На неподдерживаемую будущую schema выдавать ошибку без перезаписи. Слот не попадает в UI до полной публикации поколения.

Снимок UI-independent: при сохранении прочитать согласованную копию GameState и только ее сериализовать. Не читать меняющееся состояние по частям между кадрами. Ошибка диска не меняет активную сессию и не сообщает «сохранено».

## Ответственность AS

Формат GameState и ProfileState — 00_CONTRACTS. Полная проверка candidate state до применения: schema/contentVersion, command/resource IDs, типы/границы, callStack, phases, индексы текста, snapshot limits. Для первой версии поддерживаются сохранения с тем же contentVersion; несовпадение — понятная ошибка несовместимости. Автомиграции будущего контента не добавлять без явной mapping-таблицы.

Загрузка транзакционна: прочитать/проверить candidate, подготовить ресурсы, затем заменить Session state и построить представление. При ошибке оставить предыдущую сессию и экран доступными. Во время загрузки и удаления controls disabled, повторный click не создает вторую операцию.

Ручное сохранение в WaitingText сохраняет точный visibleIndex, wait и phase. WaitingChoice сохраняет текущие доступные варианты и их ID. WaitingTransition — descriptors/progress. Короткий Ready-пакет не прерывается кнопкой; запрос обрабатывается после ближайшего согласованного yield. Сохранение и загрузка не модифицируют counters и history.

## Политика слотов v1

- Manual: страницы 1..10, на каждой 6 слотов, ID `p01_s01`..`p10_s06`. Пустой слот сохранения активен, пустой слот загрузки неактивен. Перезапись требует Confirm.
- Quick: 6 кольцевых слотов `q01`..`q06`. QuickSave занимает следующий; QuickLoad выбирает последний валидный по sequence metadata, не по локализованной дате. Без quick saves кнопка disabled.
- Auto: 6 кольцевых слотов `a01`..`a06`. Сохранять при входе в Choice и после применения выбора при достижении первого следующего yield; одинаковый state hash не создает дубликат. Дополнительно каждые 5 минут активного narrative времени на ближайшем yield. В главном меню и при modal авто-save не запускать.
- Profile: слот `profile/main`, без thumbnail. Писать после изменения настроек с debounce 0.5 сек и при выходе/возврате в главное меню. Прочитанность flush на тех же точках и после каждой новой Choice.

Политика выше закреплена для переноса и не зависит от неявных Ren’Py defaults. Исходные названия вкладок и графика сохраняются.

## Миниатюры и экран

Thumbnail 384×216, RGB PNG, сцена 16:9 без UI меню/Confirm/Notify, с диалогом и персонажами текущего игрового состояния. При отсутствии игрового кадра сохранение недоступно. Renderer capture — универсальный механизм движка. Публикация слота требует готовой картинки; ошибка картинки не портит прежний слот.

Экран Save/Load: общий prefab, GridLayoutGroup 3 columns ×2 rows, вкладки manual/auto/quick, page navigation, thumbnail, дата/время, имя сцены/пустое состояние. Metadata UTC переводится в текущую системную локаль пользователя только при показе. Delete/перезапись/загрузка поверх сессии подтверждаются; quick load также требует подтверждения при активной сессии. После успешной загрузки закрыть меню, сбросить pending input, показать восстановленный state.

## Проверки

Round-trip после полного закрытия приложения для ADV-midprint, explicit wait, NVL, choice, call stack depth>1, перехода, loop audio. Ошибка чтения/schema/contentVersion/hash/записи; отсутствие каталога; поврежденный current с валидным previous; прерывание до/после marker replace; enumeration после нового запуска; manual overwrite; кольцевой quick/auto; отмена Confirm. Повторная загрузка не начисляет очки. Никаких SFX «догоняющего» восстановления.

## Приемка

Сохранения физически переживают перезапуск. Стенд проверяет атомарность и fallback, а не только сериализацию в памяти. `Reports/07_RESULT.md`: реальный формат, location identity, ошибки, trace восстановлений, схема диск/AS, пользовательские шаги fault-injection. Запрет самостоятельного запуска из CLAUDE.md сохраняется.
